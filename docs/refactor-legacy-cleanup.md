# حذف پیاده‌سازی قدیمی فروشگاه — ۲۰۲۶-۱۰-۱۰

فروشگاه جدید از Theme، مدل‌ها و endpointهای بومی nopCommerce و کامپوننت‌های WASM استفاده می‌کند. مصرف‌کننده‌های باقیماندهٔ پیاده‌سازی اولیه منتقل شدند و ده فایل بدون مصرف حذف شدند: `StorefrontRoot` و code-behind، `ProductCard` و `CartItem` قدیمی و code-behindهایشان، `ColorFilter`، `StorefrontService`، view مستقل `Index` و `PreviewStore`.

مسیر `/stationery/login` اکنون یک view کوچک در `_MadadrangRoot` است. همان دیالوگ BB در `NativeHeader` با پارامتر `OpenLoginOnLoad` باز می‌شود و صفحه توکن antiforgery دارد. APIهای آزمایشی OTP با محدودیت Development و ورود/ادغام سبد بومی باقی‌اند. APIهای اختصاصی catalog، quote، cart، add و quantity حذف شدند؛ تست‌هایشان از فرم‌ها و پاسخ‌های بومی استفاده می‌کنند. Swagger و Scalar فقط دو endpoint OTP را مستند می‌کنند.

ثبت Blazor Server، Hub و کپی runtime سرور از پلاگین حذف شدند. DTOهای قدیمی محاسبهٔ قیمت و جمع سبد در مرورگر هم حذف شدند. هشت محصول نمونه و گزینه‌هایشان اکنون فقط در `SampleCatalog` سمت پلاگین قرار دارند؛ seed و repair همچنان صریح و محافظت‌شده‌اند. داده‌های نمونهٔ مرورگر و منطق خرید شبیه‌سازی‌شده در Preview حذف شدند. خود پروژهٔ Preview برای آزمایش مستقل `/renderer/auto` باقی است؛ این پروژه فروشگاه یا API خرید ندارد.

CSS، exportهای JavaScript و iconهای بدون مصرف حذف و CSS تولیدشده با Tailwind بازسازی شد. تصاویر فعلی، فونت و مجوزها، `StoreSelect`، اجزای بومی و ابزارهای اجرای محلی/seed/فرمت/مدیریت هنوز مصرف دارند و حفظ شدند. گزارش‌های قدیمی به‌عنوان شواهد تاریخی باقی‌اند.

مطابق تصمیم کاربر، gateهای انتظار بررسی مرورگر و تغییر نقش Registered که فقط برای آن بررسی بود حذف شدند. اجرای تست‌ها به `.ready`/`.done` یا مرورگر وابسته نیست. helper پاک‌سازی سبد شناسه‌ها را از صفحهٔ کامل می‌خواند تا cap صفر یا خاموش‌بودن mini-cart باعث باقی‌ماندن ردیف‌ها نشود.

بررسی دستی کاربر: دیالوگ `/stationery/login`، ورود از Header و افزودن/تغییر تعداد در پنل سبد، در موبایل و دسکتاپ. تست HTTP و HTML اولیه مدرک عملکرد بصری یا کلیک مرورگر نیستند.

شواهد اجرا: build کامل پلاگین و publish بستهٔ Client موفق شدند؛ build کامل فقط هشدار موجود `CS0108` در فایل تولیدشدهٔ سرویس VAT داشت. build افزایشی پلاگین و build Preview بدون هشدار و خطا موفق شدند. مجموعهٔ کامل TUnit روی میزبان محلیِ به‌روز شامل **۴۱ تست موفق، صفر شکست و صفر skip، در ۵۰٫۵۱۷ ثانیه** بود. هفت تست هدفمند ورود/API هم پاس شدند؛ OTP و cooldown/replay، انتقال و ادغام سبد مهمان، مالکیت، CSRF، قیمت/موجودی بومی، HTML اولیهٔ ورود WASM و حذف مسیرهای تکراری بررسی شدند. بررسی مستقل Sol/xhigh مشکل مسدودکننده پیدا نکرد. هیچ push، deploy یا بررسی مرورگری اجرا نشد.

قالب‌بندی C# با `dotnet format whitespace` رسمی انجام شد؛ بررسی فایل‌های تغییرکردهٔ پلاگین، UI و تست‌ها و `git diff --check` موفق بود. `Storefront.Preview/Program.cs` همچنان تعارض از قبل ثبت‌شدهٔ SDK را در انتهای فایل دارد: `WHITESPACE` درخواست افزودن CRLF و `FINALNEWLINE` درخواست حذف همان CRLF می‌دهد. خروجی formatter حفظ شده و فرمت دستی یا تغییر قواعد برای پنهان‌کردن آن انجام نشده است. build این پروژه موفق است.
