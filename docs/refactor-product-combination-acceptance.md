# اطلاعات و تصاویر ترکیب محصول — بخش ۲

تاریخ: ۲۰۲۶-۱۰-۱۰ به وقت تهران. معماری Astra و بازبینی Sol/high مبنا هستند. مطابق تصمیم جدید کاربر، بررسی بصری و computer-use با Luna حذف شده‌اند؛ آزمون خودکار HTTP و قرارداد اولیه انجام می‌شود و بررسی مرورگر به کاربر سپرده شده است.

منطق نمایش موجود حفظ شد: کامپوننت اطلاعات و قیمت پایه را با مقدار پاسخ بومی جایگزین می‌کند، مقدار خالی را نگه نمی‌دارد و تصاویر را فقط با flag اولیهٔ بومی محدود می‌کند. طرح اصلاح مستقل URL اصلی/full-size در بازبینی اختیاری شناخته شد؛ endpoint فعلی هر دو URL را با هم یا هر دو را خالی برمی‌گرداند، بنابراین برای این بخش تغییر کد اجرایی لازم نشد. هسته و ادمین تغییر نکردند.

## آزمون بومی

`NativeProductCombinationPresentationTests` از helper محافظت‌شدهٔ توسعه، ورود بومی ادمین و HTTP دارای antiforgery استفاده می‌کند. یک محصول موقت با موجودی بر اساس ویژگی، یک ویژگی رنگ و سه مقدار، دو ترکیب و سه تصویر واقعی محلی می‌سازد. ترکیب اول SKU/MPN/GTIN و دو تصویر دارد، ترکیب دوم اطلاعات و تصویر ندارد و مقدار سوم هیچ ترکیبی ندارد. اطلاعات محصول پایه ابتدا خالی‌اند؛ nopCommerce اطلاعات خالی ترکیب را از محصول پایه جایگزین می‌کند، بنابراین خالی‌بودن پایه شرط لازم آزمون clearing است.

آزمون این موارد را اثبات می‌کند:

- ذخیرهٔ واقعی مقدارها و ترکیب‌ها از grid بومی؛ موفقیت popup صرفاً از HTTP 200 نتیجه نمی‌شود. دو PictureId انتخاب‌شده از فرم ویرایش ترکیب دوباره خوانده می‌شوند؛ شناسهٔ تصویر با شناسهٔ ردیف ProductPicture اشتباه گرفته نمی‌شود.
- HTML اولیه سه thumbnail دارد؛ قرارداد سریال‌شدهٔ واقعی کامپوننت WASM شامل سه تصویر، flag گالری، metadata پایهٔ خالی و قیمت پایهٔ غیرخالی است. URL تصویر اصلی و full-size اولیه با اولین تصویر گالری مقایسه می‌شوند. این قرارداد، اثبات DOM پس از تعامل نیست.
- پاسخ ترکیب دارای اطلاعات شامل شناسه‌های دقیق و URL اصلی/full-size متناظر با همان PictureId است. انتخاب ترکیب خالی و انتخاب بدون ترکیب، هرکدام پس از انتخاب دارای اطلاعات، metadata و فهرست تصاویر خالی برمی‌گردانند.
- با قراردادن اطلاعات غیرخالی روی محصول پایه، هر دو انتخاب خالی/بدون ترکیب به اطلاعات پایه بازمی‌گردند.
- خاموش/روشن‌کردن تنظیم تصاویر از ادمین، پس از GET تازه، flag قرارداد کامپوننت را تغییر می‌دهد؛ پاسخ بومی ترکیب همچنان همان دو PictureId را دارد.
- غیرفعال/فعال/غیرفعال‌کردن قیمت پایه با همان session و token مهمان و بدون reload فروشگاه، به‌ترتیب پاسخ `null`، متن فرمت‌شدهٔ غیرخالی و `null` می‌دهد. از این پاسخ‌ها، پاک‌شدن متن در مرورگر نتیجه گرفته نمی‌شود.

Edit محصول همان پیکربندی کامل محصول ساخته‌شده را با `LastStockQuantity` خوانده‌شده از فرم می‌فرستد و metadata و checkboxهای تغییرکرده را دوباره از ادمین می‌خواند. تنظیم عمومی یا مجوزی تغییر نمی‌کند؛ gate مرورگر، mock پاسخ و API جدید وجود ندارد.

## پاک‌سازی و نتیجه

پاک‌سازی ابتدا ترکیب‌ها را حذف و خالی‌بودن grid را بررسی می‌کند؛ سپس mapping و مقدارها، ردیف‌های تصویر و فایل‌ها، محصول با soft delete بومی و ویژگی سراسری متعلق به آزمون حذف می‌شوند. تصویر تا زمانی که association باقی باشد حذف نمی‌شود. خطاهای مراحل مستقل جمع می‌شوند و خطای اصلی آزمون در گزارش حفظ می‌شود. حذف نرم محصول به معنی حذف فیزیکی همهٔ رکوردهای پایگاه نیست.

اجرای هدفمند: یک تست موفق در ۴٫۶۰۴ ثانیه. اجرای نهایی کامل، پس از اضافه‌شدن دو assertion پیشنهادی بازبین، با fixture ادمین فعال و gate مرورگر غیرفعال: ۳۹ تست موفق، صفر شکست و صفر skip در ۳۲٫۶۳۹ ثانیه. Build پروژه‌های UI و TUnit با صفر خطا و هشدار موفق بود؛ formatter رسمی مایکروسافت و بررسی whitespace نیز پاس شدند. یک خطای اولیهٔ setup اصلاح شد: grid بومی نام رنگ را همراه RGB نمایش می‌دهد؛ شناسهٔ مقدار اکنون با `ColorSquaresRgb` واقعی پیدا می‌شود. پاک‌سازی همان اجرای ناموفق نیز خطایی نداشت.

بازبین تازهٔ `gpt-6.1-sol/xhigh` کد fixture و پاک‌سازی را تأیید کرد. پیشنهاد اختیاری مقایسهٔ تصویر اصلی/full-size اولیه اعمال و در بازبینی کوتاه بعدی تأیید شد. بازبین مرورگر یا تست دیگری اجرا نکرد؛ نتیجهٔ اجرای TUnit متعلق به اجرای اصلی محلی است.

## بررسی دستی کاربر

در دسکتاپ و موبایل، روی محصول دارای ترکیب‌های مناسب بررسی شود:

1. انتخاب دارای کدها → انتخاب خالی → انتخاب دارای کدها → انتخاب بدون ترکیب؛ ردیف‌های اطلاعات قدیمی باید ناپدید شوند.
2. با flag گالری روشن، فقط تصاویر ترکیب دیده شوند؛ انتخاب با pictureIds خالی همهٔ تصاویر را برگرداند. با flag خاموش و reload، محدودیت thumbnail اعمال نشود. پاسخ URL خالی نباید تصویر اصلی/zoom انتخاب‌شده را به تصویر پیش‌فرض برگرداند.
3. قیمت پایه ابتدا دیده شود؛ پس از غیرفعال‌کردن از ادمین، در همان صفحهٔ باز یک ویژگی یا تعداد تغییر کند و متن قبلی پاک شود. برای موبایل نیز ابتدا قیمت پایه دوباره فعال و قابل‌مشاهده شود.
4. تصاویر، BB Dialog، بستن با Escape، بازگشت focus، RTL و سرریز افقی بررسی شوند.

محصول آزمون خودکار پس از اجرا پاک می‌شود. هیچ تصویر یا پذیرش بصری جدید ثبت نشده است؛ این گزارش پذیرش HTTP/قرارداد است و هدف کل roadmap را کامل اعلام نمی‌کند.
