# Public storefront Persian resources

Source audit and pack validation: 2026-10-12. No database was modified or queried by this task. Existing QA databases may contain their own additional translations; these source counts do not measure their rows.

The existing `PersianAdminResourcesStartup` imports `PersianAdmin/fa-IR.admin.xml` at startup order 50. It creates the Persian language if missing and loads administrator translations, common labels, and a limited set of account labels. The file includes 608 non-`Admin.*` resources, mainly enums/activity/security. `Installation/installation.fa-IR.xml` translates installation screens; it is not a public-store language pack. Native `defaultResources.nopres.xml` supplies English resources, not a complete Persian public interface.

`PersianPublic/fa-IR.public.xml` supplies 1119 native Persian resources shared by both themes. The initial 529 labels cover header/footer/newsletter, catalog search/filter/paging, products/reviews/comparison, cart/wishlist, checkout, account/address/password pages, orders and returns. The subsequent 590 translations complete every remaining native key outside the `Admin.` namespace: account validation/privacy/multi-factor/external authentication; all cart warnings; shipping/shipments; downloadable products; rewards; vendors; private messages; blog; image descriptions and accessibility labels; selector labels; notification/mail order summaries; route literals; root page/menu labels; native technical diagnostic messages. The root key `Admin` itself is included because it has no `Admin.` prefix. No missing key is hidden by a prefix exception or replaced with an invented generic label. Placeholders, formatting-only values, HTML and technical identifiers retain their native contracts. Brand names and administrator-authored menu/category/topic contents are data, not locale resources; this pack does not rename them.

`PersianPublicResourcesStartup` runs at order 51, after the administrator startup creates the language and before native culture setup at order 100. It prefers the XML embedded in the current plugin assembly under `Nop.Plugin.Misc.PersianStorefront.Localization.fa-IR.public.xml`; an older persistent `App_Data` volume therefore cannot mask the shipped revision. File-only development hosts fall back to `App_Data/Localization/PersianPublic/fa-IR.public.xml` when the assembly has no embedded pack. It calls native `ILocalizationService.ImportResourcesFromXmlAsync` with `updateExistingResources: false`. Native import skips every existing resource, inserts missing rows and invalidates locale caches. It does not replace administrator translations, copied English values, empty custom values, or deleted/changed language settings; the startup does not create or republish languages itself. A pack missing from both locations logs a warning and preserves existing language behavior.

Native Nop.Web publishing copies `App_Data/**`, and the plugin project also embeds the shared XML. Rebuild and deploy the plugin assembly with its corresponding release; changing a file alone does not replace the embedded resource of an old assembly. This avoids needing to overwrite a container's persisted App_Data configuration merely to ship public labels. For already-running QA instances, restart the rebuilt isolated package to import missing labels into its own database copy. No additional SQL migration is needed for those keys. The unrelated `docker/madadrang-public-resources.sql` remains unchanged.

To import a reviewed complete translation pack without overwriting merchant choices, use the native service with `updateExistingResources: false`. The native administration import uses its configured update behavior; do not assume it preserves existing translations. The separate administrator baseline importer can update unchanged managed administrator translations by design; this public importer has a stricter missing-only policy.

Combined with the unchanged administrator file, source translations cover **1718 of 1718 native non-`Admin.*` resources (100%)**. The public XML has 1119 entries; the administrator XML has 608 non-`Admin.*` entries, with nine names overlapping the public pack. The overlaps are from the initial public pack; existing translations retain precedence through missing-only import. Completeness is checked against the exact native `defaultResources.nopres.xml` entry set, including technical/enum/activity keys already covered by the administrator pack. The coverage test fails for an additional native source key or a removed translation. Plugin-supplied resources outside that native source set must be supplied by their plugins and are not included in the 1718 denominator.

Source completeness is not a database or browser assertion: existing custom translations (including English or empty values) are preserved, so a database may intentionally differ. Deploy both XML packs, enable the Persian language through normal configuration, and verify the rendered enabled-feature pages in the isolated instances. No existing administrator translation or merchant data was changed to force a percentage.

Eight pure cases pass: the six pack contracts (unique known nonempty labels, numbered placeholders, HTML, percent tokens, required header/footer/catalog keys and exact public coverage), plus two old/missing persisted-file cases that read the shipped embedded pack instead. This does not execute the database importer.
