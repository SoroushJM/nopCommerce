# گزارش بررسی فروشگاه — 2026-10-03

بررسی روی Windows و Chrome با Computer Use انجام شد. برنامهٔ اصلی nopCommerce در localhost:5090، پلاگین نصب‌شده و PostgreSQL واقعی استفاده شدند؛ تصاویر این گزارش از preview مستقل نیستند. desktop viewport برابر 1440×900 و mobile viewport برابر 390×844 بود. موبایل شبیه‌سازی اندازهٔ Chrome است؛ دستگاه فیزیکی آزمایش نشده است.

## ایرادهای پیدا و رفع‌شده

- اسکریپت `blazor.server.js` ابتدا 404 بود و صفحه فقط prerender داشت. فایل رسمی framework داخل پلاگین کپی و middleware قبل از routing ثبت شد؛ تغییر رنگ و افزودن واقعی پس از اصلاح در مرورگر تأیید شد.
- Sheet باریک قیمت را می‌برید و اسکرول افقی داشت؛ grid داخلی دو ستون شد و عرض پنل با موبایل سازگار شد.
- منوی پایین موبایل روی دکمهٔ Sheet می‌افتاد؛ لایهٔ منو زیر overlay قرار گرفت.
- فیلد موبایل ابتدا همیشه disabled بود؛ عبارت Boolean Razor اصلاح شد. binding ورودی phone/code به oninput تغییر کرد تا مقدار فرم به API برسد.
- مرتب‌سازی پیش‌فرض به خاطر query خالی، گزینهٔ خالی نشان می‌داد؛ default popular حفظ شد.
- احراز هویت استاندارد nopCommerce برای حساب بدون email/password record پایدار نبود؛ شناسهٔ داخلی ایمیل و رمز تصادفی داخل پلاگین اضافه شد. سپس refresh و انتقال/ادغام سبد پاس شدند.
- Swagger کنترلر پایه را شامل متد بدون HTTP verb می‌دید؛ API از ControllerBase با filterهای دسترسی و antiforgery صریح استفاده می‌کند.
- publish با package.jsonهای چند پروژه تداخل داشت؛ فایل‌های npm از publish UI خارج و project reference وب private=false شد. assets رابط در Content خروجی انتشار کپی می‌شوند.

## آزمون اتصال واقعی

`scripts/test-storefront.ps1` اجرا و همهٔ assertionها پاس شدند:

- token ضد جعل درخواست، انتخاب ویژگی و قیمت واقعی؛
- افزودن مهمان، جلوگیری از خرید ترکیب ناموجود؛
- OTP اشتباه، محدودیت درخواست دوباره و جلوگیری از replay؛
- ورود پایدار، انتقال سبد مهمان و ادغام با سبد قبلی حساب؛
- جلوگیری از دست‌کاری سبد مشتری دیگر؛
- تغییر تعداد، جمع قیمت و حذف؛
- رد POST بدون antiforgery؛
- سند OpenAPI هفت مسیر، Swagger UI و Scalar.

آزمون جداگانه در Production روی localhost:5091 نشان داد ارسال mock OTP با 503 بسته است و سند OpenAPI با 404 در دسترس نیست. آن فرایند پس از آزمون متوقف شد. HTML ورود اصلی `/login?returnUrl=/Admin` فاقد Storefront.UI بود؛ هیچ فایل Areas/Admin یا هسته در diff تغییر نکرده است. ورود کامل مدیر با رمز در مرورگر اجرا نشده است.

build پلاگین و preview مستقل با صفر warning/error پاس شد. `dotnet publish` پلاگین نیز پاس شد و وجود CSS فروشگاه، CSS کتابخانه، فونت Vazirmatn و `blazor.server.js` در Content خروجی بررسی شد. اطلاعات اتصال و حساب مدیر در فایل‌های محلی ignored باقی ماندند.

## حدود بررسی

نمونهٔ واقعی انتخاب ویژگی در این پایگاه روی رنگ آزمایش شد؛ نمایش گزینهٔ متنی مدل پشتیبانی می‌شود ولی نمونهٔ مستقل مدل در کاتالوگ آزمایش نشده است. صفحه‌های کم‌مراجعه و ادمین بازطراحی نشدند. پرداخت، ارسال و سفارش نهایی در این فاز نیستند. بررسی صفحه‌خوان کامل، دستگاه فیزیکی، بار، کاتالوگ بزرگ، درگاه واقعی و پیامک واقعی انجام نشده است. تصاویر نمونه و برند موقت پیش از فروش واقعی باید با اطلاعات فروشگاه جایگزین شوند.
