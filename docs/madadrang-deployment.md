# Deploy مدادرنگ و داده‌های نمونه

از ریشهٔ پروژهٔ Compose نصب‌شده اجرا کنید:

```sh
# deploy معمولی؛ بدون ساخت دادهٔ نمونه
sh deploy.sh

# deploy همراه کاتالوگ نمونه
sh deploy.sh --seed-data

# انتشار ایمیجی که قبلاً روی سرور load شده است
sh deploy.sh --image nopcommerce:my-release --seed-data
```

اسکریپت ایمیج نمی‌سازد و دانلود نمی‌کند. بدون `--image`، همان ایمیج کانتینر فعلی را استفاده می‌کند. با `--image`، ایمیج مشخص‌شده را به نام ایمیج سرویس وب در تنظیمات همان Compose تگ می‌کند؛ نام پروژه یا ایمیج در اسکریپت ثابت نیست. `--store-id 1` شناسهٔ فروشگاه را تعیین می‌کند؛ پیش‌فرض `STORE_ID` یا `1` است. `--help` بدون دسترسی به Docker راهنما را نمایش می‌دهد.

## چرا فقط تغییر ایمیج کافی نبود؟

قالب مدادرنگ از منو و widgetهای بومی nopCommerce استفاده می‌کند. اسلایدر iPhone/Salaxy، منوهای انگلیسی و زبان پیش‌فرض در دیتابیس قبلی باقی مانده بودند. اسکریپت قدیمی فقط ایمیج و نام قالب را تغییر می‌داد؛ در نتیجه اجزای پیش‌فرض کنار طراحی مدادرنگ نمایش داده می‌شدند. آماده‌سازی ظاهر اکنون بخشی از deploy است و به اجرای کد مخصوص Development وابسته نیست.

## آماده‌سازی و انتقال فایل‌ها

این مسیر برای یک فروشگاه مستقل **Madadrang با PostgreSQL** است. به Linux، Docker Compose v2، Python 3 و `flock` نیاز دارد. ابتدا نصب nopCommerce را تمام کنید و پلاگین `Misc.PersianStorefront` را در پنل مدیریت نصب کنید. اسکریپت دیتابیس را حذف یا nopCommerce و پلاگین‌ها را نصب نمی‌کند. بدون seed، زبان `fa-IR` باید منتشرشده و راست‌به‌چپ باشد؛ seed در صورت نبودن، فارسی و تومان را ایجاد می‌کند.

فایل `deploy.sh` را در ریشهٔ پروژه و این فایل‌ها را در پوشهٔ `docker/` پروژهٔ نصب‌شده کپی کنید:

```text
deploy-madadrang.sh
madadrang-presentation.sql
madadrang-public-resources.sql
verify-madadrang.py
generate-madadrang-seed.py
madadrang-seed.json
test-madadrang-deployment.sh
```

فایل JSON شامل تصاویر هم هست؛ برای seed به سورس یا پوشهٔ تصاویر روی سرور نیاز نیست. SQL مربوط به seed فقط هنگام درخواست آن تولید می‌شود. فایل‌های پروژهٔ نصب‌شده، `.env` و volumeها را حفظ کنید. از همان تنظیمات Compose آن instance استفاده کنید؛ عوض‌کردن نام پروژه، پروژه و volumeهای دیگری را انتخاب می‌کند.

برای انتقال از Windows:

```powershell
scp deploy.sh ubuntu@188.121.123.191:/opt/nopcommerce/
scp docker/deploy-madadrang.sh docker/madadrang-presentation.sql docker/madadrang-public-resources.sql docker/verify-madadrang.py docker/generate-madadrang-seed.py docker/madadrang-seed.json docker/test-madadrang-deployment.sh ubuntu@188.121.123.191:/opt/nopcommerce/docker/
ssh ubuntu@188.121.123.191
```

سپس روی سرور:

```sh
cd /opt/nopcommerce
sh deploy.sh --seed-data
```

اگر Compose این instance از فایل‌های غیرپیش‌فرض استفاده می‌کند، پیش از اجرای اسکریپت متغیرهای استاندارد Compose را تنظیم کنید. مثلاً:

```sh
export COMPOSE_FILE=docker-compose.yml:docker-compose.small-host.yml
# فقط وقتی instance از این فایل استفاده می‌کند:
export COMPOSE_ENV_FILES=/absolute/path/madadrang-test.env
sh deploy.sh --seed-data
```

## رفتار deploy و seed

deploy معمولی ظاهر اولیه را یک بار آماده می‌کند: قالب مدادرنگ، زبان عمومی فارسی، سه منوی قابل‌ویرایش، مسیرهای بومی و ترجمه‌های عمومیِ مفقود. فقط اسلایدر، منوها و متن خوشامدگوییِ دست‌نخوردهٔ نصب اولیه غیرفعال می‌شوند. نسخهٔ اعمال‌شده در ویژگی‌های فروشگاه ثبت می‌شود تا deploy بعدی تغییرات مدیر را برنگرداند. ترجمه‌های موجود جایگزین نمی‌شوند.

`--seed-data` هشت محصول `MRG-1` تا `MRG-8`، چهار دسته، برندها، تصاویر و چهار گزینهٔ رنگ برای هر محصول را اضافه می‌کند. اولین seed، نمایش نمونه‌ها در صفحهٔ اصلی و تومان را هم تنظیم می‌کند. محصول دارای SKU موجود دوباره ساخته نمی‌شود و قیمت یا موجودی آن بازنویسی نمی‌شود. محصولی که به‌صورت soft delete حذف شده نیز دوباره فعال نمی‌شود. حذف کامل رکورد نمونه و درخواست مجدد seed می‌تواند آن را دوباره بسازد.

می‌توانید seed را بعد از یک deploy معمولی اجرا کنید. اجرای مجدد روی دادهٔ کامل محصول، تصویر یا منوی تکراری نمی‌سازد. بعد از ویرایش کاتالوگ، معمولاً deploy را بدون این فلگ اجرا کنید: بررسی حالت seed انتظار دارد حداقل چهار دسته و هشت محصول در صفحهٔ اصلی و قیمت به تومان دیده شوند. اگر عمداً نمونه‌ها را مخفی کرده‌اید، این بررسی می‌تواند خطا بدهد.

برای جلوگیری از تغییر معنای قیمت‌های موجود، اولین seed روی کاتالوگ غیرنمونه با ارز پایهٔ دیگری رد می‌شود. در آن حالت ارز و قیمت‌های کاتالوگ را ابتدا از پنل مدیریت آماده کنید. این اسکریپت برای Boutique، MySQL یا چندفروشگاهی نیست.

## مراحل اجرا و نتیجه

1. ورودی‌ها، ایمیج قالب و نصب پلاگین را بررسی می‌کند و جلوی deploy هم‌زمان را می‌گیرد.
2. فقط سرویس وب را متوقف و از دیتابیس، `App_Data` و تنظیمات Compose بکاپ می‌گیرد.
3. آماده‌سازی ظاهر و seed اختیاری را در یک transaction اجرا می‌کند.
4. وب را با ایمیج انتخاب‌شده بالا می‌آورد و منتظر سلامت کانتینر می‌ماند.
5. صفحهٔ عمومی، فارسی/RTL، نبودن محتوای نمونهٔ قدیمی، تصاویر، CSS و مسیرهای دسته/محصول را بررسی می‌کند. در حالت seed، نمایش کاتالوگ و تومان هم بررسی می‌شود.

موفقیت با پیام `Deployment verified. Backup: ...` و exit code صفر مشخص می‌شود. سلامت فایل favicon به‌تنهایی موفقیت deploy محسوب نمی‌شود. اگر SQL خطا بدهد، transaction برمی‌گردد و وب قبلی شروع می‌شود. اگر راه‌اندازی یا بررسی صفحه پس از commit شکست بخورد، اسکریپت خطا و مسیر بکاپ را گزارش می‌کند؛ تغییرات commit‌شده را خودکار برنمی‌گرداند.

## بکاپ و برگشت دستی

هر بار پوشه‌ای با نام `backups/presentation-<UTC timestamp>-<pid>/` ایجاد می‌شود. شامل `database.dump`، `App_Data`، فایل‌های Compose، اطلاعات ایمیج و وضعیت سرویس‌ها است. ایمیج قبلی نیز با تگ `nopcommerce:rollback-<timestamp>-<pid>` نگهداری می‌شود. این پوشه شامل اطلاعات خصوصی فروشگاه است.

برای برگشت فقط ایمیج، از تگ rollback چاپ‌شده استفاده کنید:

```sh
sh deploy.sh --image nopcommerce:rollback-<timestamp>-<pid>
```

این دستور دیتابیس را به زمان بکاپ برنمی‌گرداند. برای برگشت کامل، وب را متوقف کنید، `database.dump` و `App_Data` همان بکاپ را بازیابی کنید و Compose/ایمیج ذخیره‌شده را بالا بیاورید. بازیابی دیتابیس، تغییرات بعد از زمان بکاپ را حذف می‌کند؛ آن را صرفاً برای خطای تأیید صفحه اجرا نکنید.

## تست

این دستور از دیتابیس نصب‌شده یک کپی موقت می‌سازد و فقط همان کپی را تغییر می‌دهد؛ لازم نیست قبل از اولین deploy اجرا شود:

```sh
sh docker/test-madadrang-deployment.sh
# یا از بکاپ نصب‌شده به‌عنوان مبنا:
sh docker/test-madadrang-deployment.sh backups/presentation-<timestamp>-<pid>/database.dump
```

تست، deploy بدون seed، ساخت واقعی محصولات/تصاویر/تنوع‌ها بعد از آن، تکرار seed، حفظ قیمت و موجودی و منو و ترجمه‌های ویرایش‌شده، و ردکردن قالب دیگر را بررسی می‌کند. برای بررسی تغییرناکردن داده‌ها، checksum خروجی کامل دیتابیس مقایسه می‌شود. کپی موقت در پایان حذف می‌شود. مبنای این تست باید زبان فارسی منتشرشده داشته باشد؛ برای تست تازه‌سازی seed از همین نصب آزمایشی استفاده کنید.

برای تست مسیر واقعی انتشار، پس از این تست دیتابیس، یک deploy با seed و یک deploy بدون seed اجرا کنید. هر دو باید پیام موفقیت بالا را چاپ کنند. فایل‌های این پوشه همراه انتشار منتقل شوند؛ انتقال تنها ایمیج، آماده‌سازی دیتابیس را اجرا نمی‌کند.
