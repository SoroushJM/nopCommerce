# تقویم فایل‌های مدیریت

کنار کنترل‌های خروجی و PDF انتخاب «شمسی / میلادی» قرار دارد. انتخاب خروجی در همان صفحه مشترک است؛ تقویم فایل ورودی Excel باید صریحاً انتخاب شود.

انتخاب‌گر در ۲۱ صفحهٔ اصلی مدیریت با Partial View مشترک Razor نمایش داده می‌شود. در ادغام ۲۰۲۶-۱۰-۱۵، تغییرات فارسی به مسیر اصلی `Areas/Admin/Views` برگشتند. `AdminCalendarViewLocationExpander` افزونه ثبت نمی‌شود؛ فایل‌های افزونه مرجع اجرای این صفحات نیستند. این تغییرها در استثنای مجاز فارسی‌سازی پنل ادمین قرار دارند.

انتخاب «اعمال» با فرم POST معمولی به `Common.SetTransferCalendar` در مدیریت می‌رسد و در cookie اختصاصی ذخیره می‌شود. لینک‌های دانلود و فرم‌های خروجی، تقویم ذخیره‌شده را صریحاً ارسال می‌کنند؛ برای تغییر تقویم ابتدا «اعمال» را بزنید. layoutهای مدیریت فرم ذخیرهٔ ترجیح را بعد از محتوای صفحه و خارج از فرم‌های آن قرار می‌دهند؛ انتخاب‌گر با ویژگی استاندارد HTML `form` به آن متصل می‌شود. تزریق انتخاب‌گر، بازنویسی لینک‌ها یا AJAX prefilter اختصاصی برای تقویم وجود ندارد. تبدیل و اعتبارسنجی فایل‌ها با فیلتر موجود در افزونه انجام می‌شود.

هنگام ارتقای nopCommerce، تغییرات فارسی این ۲۱ صفحه باید با نسخهٔ جدید صفحات اصلی ادغام شوند. سفارشی‌سازی صفحات عمومی فروشگاه در تم‌ها و افزونه باقی می‌ماند؛ اسکریپتی فایل‌های هسته را در زمان اجرا بازنویسی نمی‌کند.

- در XLSX شمسی، سلول‌های تاریخ به متن `yyyy/MM/dd HH:mm:ss.fffffff` تبدیل می‌شوند. ساعت و دقت زمان حفظ می‌شود؛ تبدیل تقویم، منطقه زمانی را تغییر نمی‌دهد.
- برگه مخفی `__NopCalendar` نوع تقویم، قالب و آدرس سلول‌های تاریخ را ثبت می‌کند. هنگام ورود مجدد، انتخاب تقویم باید با مشخصات فایل مطابقت داشته باشد. تاریخ‌های شمسی پیش از ورود به سرویس موجود به تاریخ میلادی برمی‌گردند.
- فایل XML شمسی روی ریشه دارای `dateCalendar="jalali"` و `dateFormat` است. نام عناصر فنی حفظ می‌شود. برای مصرف‌کننده‌ای که فقط قرارداد قدیمی را می‌پذیرد، خروجی میلادی را انتخاب کنید.
- گزارش‌های Excel در زبان فارسی یک برگه نخست با عنوان «گزارش فارسی» دارند: راست‌به‌چپ، عنوان ستون‌ها و نمایش اعداد فارسی. برگه داده با اعداد قابل محاسبه نیز حفظ می‌شود.
- عنوان خلاصه گزارش نیز از تقویم انتخابی پیروی می‌کند. گروه‌بندی ماهانه سرویس همچنان بر مبنای ماه میلادی است؛ در خروجی شمسی، بازهٔ همان ماه نمایش داده می‌شود تا با یک ماه شمسی اشتباه نشود.
- فایل XML هر دو تقویم به‌صورت UTF-8 معتبر نوشته می‌شود؛ اعلان ناسازگار UTF-16 خروجی بومی اصلاح شده است.
- فاکتور و PDF دسته‌ای مدیریت از زبان انتخابی مدیر استفاده می‌کنند. تاریخ فاکتور و یادداشت‌ها تابع تقویم انتخابی است؛ قیمت، تعداد و شماره سفارش فارسی می‌شوند. SKU، نام محصول، URL و داده‌های فنی حفظ می‌شوند. PDFهای دسته‌ای داخل ZIP نیز همین انتخاب را دارند.
- درخواست‌های مستقیم بدون انتخاب تقویم و بدون cookie ترجیح همچنان میلادی‌اند. import Excel بدون انتخاب صریح تقویم یا با انتخاب خلاف فراداده فایل رد می‌شود؛ ترجیح خروجی جایگزین انتخاب اجباری import نمی‌شود.
- ذخیره‌سازی تاریخ در پایگاه داده، API سرویس‌های اصلی، خروجی فروشگاه و قراردادهای افزونه‌ها تغییر نمی‌کنند. تبدیل فایل در مرز کنترلر مدیریت انجام می‌شود.

## بررسی

تست‌های `TransferCalendarTests` شامل نوروز، روز کبیسه معتبر/نامعتبر، ساعت و دقت هفت‌رقمی، و ورود اعداد فارسی/عربی‌اند. بررسی مرورگر باید دانلود حقیقی فایل‌های شمسی و میلادی، بازکردن XLSX/XML و PDF، و رد ورود بدون انتخاب/با تقویم نادرست را شامل شود. نتیجه اجرای نهایی بررسی‌ها در گزارش اصلی کار ثبت می‌شود.
