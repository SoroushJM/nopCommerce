# مرز تغییرات کد اصلی nopCommerce

قاعدهٔ تأییدشدهٔ کاربر در ۲۰۲۶-۱۰-۱۵: کد اصلی nopCommerce فقط برای فارسی‌سازی پنل ادمین قابل تغییر است.

فروشگاه‌های مداد رنگی و میشا شاپ از افزونهٔ `Misc.PersianStorefront`، کتابخانه‌های `src/Storefront` و تم‌های اختصاصی خود استفاده می‌کنند. برای توسعهٔ کامل، `src/Storefront.sln` را باز کنید؛ solution اصلی، `Nop.Web.csproj` و `Directory.Build.props` به نسخهٔ پیش از سفارشی‌سازی فروشگاه بازگردانده شده‌اند. تنظیمات ساخت اختصاصی در `Storefront.Build.props` و `Storefront/Storefront.Integration.targets` نگهداری می‌شوند.

layout و popup ارسال سفارشی در پوشهٔ هر تم override می‌شوند. نصب از پیش پیکربندی‌شده، انتخاب viewهای کامپایل‌شده و جداسازی نام کوکی‌ها در startup و filterهای افزونه قرار دارند. نام تنظیمات محیطی قبلی پشتیبانی می‌شود.

تغییرات مجاز ادمین شامل متن و RTL، تقویم و ارقام فارسی، نمایش تاریخ‌ها و فایل‌های خروجی ادمین است. تغییرات PDF و ExportImport فقط در همین دامنه نگهداری می‌شوند. تغییر فونت Login بومی نیز فقط هنگام ورود فارسی به مسیر ادمین فعال است.

۲۱ صفحهٔ ادمین، کنترل‌های تقویم را در مسیر اصلی خود دارند و از اکشن و partialهای ادمین استفاده می‌کنند؛ expander تقویم افزونه ثبت نمی‌شود تا فرم ترجیح تکرار نشود.

برای بررسی این مرز از ریشهٔ مخزن اجرا کنید:

```powershell
python scripts/check-nopcommerce-core.py
```

این بررسی، کد و فایل‌های پروژه را با نسخهٔ بازبینی‌شدهٔ upstream، یعنی `77d112f365e210ebdfa2f9790c8202a0e3b1c74e`، مقایسه می‌کند. این مبنا همراه با ادغام تغییرات رسمی در ۲۰۲۶-۱۰-۱۷ به‌روز شد تا اصلاحات خود nopCommerce به‌عنوان سفارشی‌سازی گزارش نشوند. مبنا فقط پس از بازبینی و ادغام نسخهٔ متناظر upstream تغییر می‌کند. فهرست استثناهای محدود فارسی‌سازی ادمین در خود اسکریپت مشخص است؛ تغییر این فهرست جای بازبینی دامنهٔ تغییر را نمی‌گیرد.

## بررسی ادغام ۲۰۲۶-۱۰-۱۵

- هر دو commit قدیمی ادمین و مستندات، snapshot کار محلی و commit ریموت `1858e67` در تاریخچهٔ نتیجه حضور دارند.
- build کامل Release افزونه، Nop.Web، هر دو رابط و Client WebAssembly موفق بود؛ کامپایل تمام viewهای بومی و هر دو تم در Nop.Docker.Views نیز با صفر خطا و هشدار موفق شد.
- پنج تست مستقل runtime برای نام‌گذاری کوکی‌ها، compiler نمای کامپایل‌شده و نصب پیکربندی‌شده با runner اصلی TUnit موفق شدند؛ اتصال به سرور یا دیتابیس نداشتند.
- چهار حالت build یعنی Madadrang، MishaShop، All و نام قدیمی Boutique از نظر ارجاعات پروژه و حذف تم غیرفعال بررسی شدند. بررسی مرز کد اصلی نیز موفق بود.
- ۲۱ صفحهٔ اصلی ادمین از نظر کنترل تقویم با نسخهٔ محلی تأییدشده مقایسه شدند. تست مرورگر و انتشار سرور در این ادغام اجرا نشد.
