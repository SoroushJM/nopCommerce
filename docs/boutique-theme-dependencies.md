# وابستگی‌های تم لباس و تم مداد رنگی

بررسی کد در ۲۰۲۶-۱۰-۱۲، در جلسهٔ grill-with-docs. این سند واقعیت‌های فعلی و تصمیم‌های باز را ثبت می‌کند؛ تصمیم نهایی دربارهٔ بسته‌بندی یا تغییر کد نیست.

## محدودهٔ مشخص‌شده توسط کاربر

- فروشگاه لباس یک تم جداگانه از Madadrang دارد.
- نصب و پایگاه دادهٔ دو فروشگاه مستقل‌اند؛ کاربر این پیشنهاد را پذیرفته است. تصمیم در [ADR-0003](adr/0003-separate-storefront-deployments.md) ثبت شده است.
- مشخصات بصری از `../../shared-chat-full.json` می‌آید؛ انتخاب‌های کاربر مبنا هستند، نه همهٔ پیشنهادهای دستیار در آن گفتگو.
- قابلیت‌ها و رفتارهای موجود nopCommerce باید حفظ شوند؛ افزودن قابلیت تجاری تازه در محدودهٔ بازطراحی نیست.
- توضیح تکمیلی کاربر: تمام قابلیت‌های موجود nopCommerce باید در هر دو تم در دسترس باشند. اگر رابط فعلی یک قابلیت موجود را نمایش نمی‌دهد یا تعامل آن ناقص است، رابط همان قابلیت تکمیل می‌شود؛ این شرط به معنی اختراع قابلیت تجاری جدید نیست. استفاده از نمایش بومی برای انواع پشتیبانی‌نشده باید همهٔ کنترل‌ها، اعتبارسنجی و نقاط توسعهٔ مربوط را حفظ کند.
- نام برند هنوز تعیین نشده است. Boutique صرفاً پیشنهاد قبلی برای شناسهٔ داخلی بود.

## تصمیم‌های تأییدشده

- ریشهٔ مشخص‌شده: تم لباس مستقل، با حفظ رفتار nopCommerce.
  - تصمیم مشخص‌شده: دو نصب و پایگاه دادهٔ مستقل.
  - کد دو تم و اجزای مشترک در همین مخزن، در سه پروژهٔ UI جدا نگهداری می‌شوند.
  - هر خروجی فقط تم انتخاب‌شده و نسخهٔ محلی Shared را حمل می‌کند؛ افزونهٔ سروری برای اتصال‌های موجود نصب می‌شود.
  - آماده‌سازی داده‌های نمونهٔ مداد رنگی در نصب لباس اجرا نمی‌شود. نام برند، تصویر اصلی و متن فروشگاه لباس از تنظیمات همان نصب خوانده می‌شوند.
  - تصمیم تفکیک UI در ADR 0004 ثبت شده است؛ تأیید نهایی ساخت و اجرای دو خروجی همچنان بخشی از کار است.

واژه‌نامهٔ فعلی `CONTEXT.md` دربارهٔ لوازم‌تحریر است و در این بررسی تغییر نکرده است؛ تصمیم استقرار در ADR ثبت شده، نه در واژه‌نامه.

## ارزیابی اولیهٔ استفادهٔ مجدد

این ارزیابی بر اساس مطالعهٔ سورس است؛ درصد خطوط مشترک یا زمان صرفه‌جویی اندازه‌گیری نشده و سازگاری فروشگاه لباس هنوز آزمایش نشده است.

- زیرساخت اجرای WASM همراه prerender، میزبانی فایل‌ها و ساخت پروژه‌ها پایهٔ قابل استفادهٔ مجدد است؛ منابع تم دوم باید به build اضافه شوند.
- `NativeProductPresentation` و `NativeCartPresentation` از مدل‌ها و مسیرهای بومی nopCommerce استفاده می‌کنند و عمدتاً مستقل از نوع کالای لوازم‌تحریرند.
- `NativeProductPage.razor.cs` انتخاب ویژگی‌ها، قیمت، ترکیب موجودی، گالری و افزودن به سبد را مدیریت می‌کند. reuse رفتار از reuse کل markup جداست؛ رنگ و سایز لباس می‌توانند از همین الگو استفاده کنند.
- `NativeProductPresentation.Supports` فقط برخی محصولات و کنترل ویژگی را می‌پذیرد. مسیر جایگزین بومی برای سایر انواع باید حفظ شود؛ این کامپوننت به‌تنهایی پوشش همهٔ قابلیت‌های محصول نیست.
- منو، کنترل فیلتر، مرتب‌سازی، صفحه‌بندی، انتخاب تعداد، مدیریت فوکوس و درخواست‌های cookie/antiforgery نامزد اشتراک‌اند. نام تم، مسیرهای ثابت و بعضی نام‌های event باید از هویت مداد رنگی مستقل شوند.
- صفحهٔ اصلی، برند، بنرها، هدر، فوتر، چیدمان و CSS اختصاصی لباس نیازمند طراحی تازه‌اند؛ اجزای کوچک می‌توانند مشترک بمانند.
- داده‌های نمونه، repairهای توسعهٔ مخصوص مداد رنگی و محتوای لوازم‌تحریر برای فروشگاه لباس مشترک نمی‌شوند.
- رفتار خرید از nopCommerce حفظ می‌شود؛ طراحی اختصاصی کامل تسویه‌حساب و حساب کاربری لباس آماده فرض نمی‌شود.

## پیشنهاد سه پروژه برای لایهٔ UI

کاربر تقسیم لایهٔ تم به یک پروژهٔ مشترک و دو پروژهٔ اختصاصی را تأیید و اجرای تفکیک همراه ساخت تم لباس را به‌صورت مرحله‌ای و موازی مجاز کرده است. نام‌گذاری `Storefront.UI.Shared`، `Storefront.UI.Madadrang` و `Storefront.UI.Boutique` است؛ نام Boutique موقت است. هر سه پروژه در همین مخزن با دو خروجی انتشار مستقل نگهداری می‌شوند.

- Shared شامل قراردادهای داده، اجزای کوچک عمومی و رفتار تعاملی قابل استفادهٔ مجدد است؛ وابستگی به دو پروژهٔ تم ندارد و به سرویس‌های سروری nopCommerce وابسته نمی‌شود.
- دو پروژهٔ تم به Shared وابسته‌اند و صفحات، ترکیب اجزا، هویت بصری و استایل اختصاصی را نگه می‌دارند. دو تم به یکدیگر وابسته نمی‌شوند.
- تغییر نام Storefront.UI به‌تنهایی کافی نیست؛ محتوای مخصوص مداد رنگی باید از Shared خارج شود.
- این سه پروژه مربوط به UI هستند؛ پروژهٔ WASM Client، افزونهٔ میزبان و پوشه‌های MVC Theme نقش‌های موجود خود را دارند و مرز آن‌ها در مرحلهٔ اجرا باید هماهنگ شود.
- ساخت Client و بستهٔ انتشار هر سایت باید به تم همان سایت وصل شود؛ Shared بخشی از خروجی محلی هر سایت است و سرویس اجرایی مشترک میان دو deploy نیست.
- آماده‌سازی مدل‌های بومی روی سرور در افزونه باقی می‌ماند. صفحات کامل صرفاً به‌دلیل شباهت، به Shared منتقل نمی‌شوند.
